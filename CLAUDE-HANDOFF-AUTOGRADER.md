## The autograder works
30 labs, 169 executable cases, every case carrying a verified expected output.
Write C in C-MON, press Run to try it, press Submit to be graded. Submit
compiles with Clang and LLD (both bundled as WebAssembly) and runs the program
in an in-memory WASI sandbox. Rewards are granted only when every test passes.
Nothing is uploaded and no compiler needs to be installed.

Verified end to end by `node tools/check-autograder.cjs`, 16/16, against an
isolated save: the reference passes and pays once, resubmitting cannot pay
twice, a one-byte trailing space fails all 9 cases of its lab, failures and
compiler errors pay nothing, an infinite loop is stopped by the watchdog, an
edited draft marks earlier results stale, and no self-review controls remain.

## What was wrong, and what fixed it

**Every file lab was silently broken, not just lab 28.** `fopen` failed with
ENOTCAPABLE (76) for reads and writes alike. The bundled libc predates WASI
preview1 and asks a directory what rights it may inherit before it will call
`path_open`; browser_wasi_shim answers `Fdstat(DIRECTORY, 0)`, i.e. no rights,
so libc refused without ever reaching the filesystem. `js/engine/c-worker.js`
now advertises full rights on directory and file descriptors, alongside the
existing seek and filestat adaptations. The sandbox boundary is the in-memory
filesystem, which holds only the current test's files, so these bits are
plumbing this libc requires rather than a control being relied on.

This mattered more than a failing lab. Labs 24 and 28 only *appeared* to run
because their references return a failure code when the file will not open. Had
the expected outputs been captured from that run, lab 28 case 5 would have been
recorded as `0 7 7` when the correct answer is `1 1025 100`, and the autograder
would have marked correct student work wrong. Expected outputs were regenerated
after the fix.

**No case had an expected output at all.** All 169 compared against `undefined`,
so nothing could ever pass. It failed safe rather than paying out, but no quest
was completable. Now generated, reviewed and stored.

**Five defects in js/engine/side-quests.js**, all fixed: the migration wiped
valid autograder submissions; grade results were never marked stale after an
edit (`lastGrade` now records the source it graded); the vestigial
`QUEST_IMPORT_SEQUENCE` was removed; the hex fixture pattern accepted contiguous
pairs like `0102` that the whitespace-splitting parser then misread as 258; and
an invalid Run fixture blocked Submit, which uses canonical fixtures instead.

## Expected outputs are reviewed, not assumed
Generated by compiling and running the reference implementations, then checked
by hand against the written contracts before use. All five file labs were
verified case by case, plus a sample across the arithmetic and validation labs:
little-endian encoding, boundary values, integer division, clamping,
transactional load, allocation failure, and 32-bit revenue overflow.

Each expectation carries a hash of the inputs that determine it (harness +
reference source + case input + case files). If a contract changes the hash
stops matching and the expectation is DROPPED, so a rebuilt lab becomes
ungradeable until re-verified rather than being graded against a stale answer.
`tools/build-quest-grader.py` now re-applies expectations at the end of every
build, so the old footgun of a rebuild silently clearing them is gone.

Pipeline: `build-quest-grader.py` -> `build-expected-outputs.cjs` (needs the
server) -> `apply-expected-outputs.cjs`. Catalog: `build-quest-catalog.cjs`.

## Deliberately left alone
`shop_load` in lab 30 parses revenue with `%lu`, which also accepts a negative
literal and wraps it. No test covers a negative revenue, so no two correct
implementations can disagree over it. Adding one would impose a rule the written
contract does not state and could fail legitimate work. Tighten the contract
wording first if it is ever worth testing.

## Trap worth knowing
Writing a literal backslash-n inside a heredoc in this environment collapses the
escape before the interpreter sees it. It has silently corrupted C sources, JS
regexes and string literals here several times. Build backslashes with `chr(92)`,
or edit by line index, and assert that the match succeeded.
